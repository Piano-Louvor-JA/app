## B1 — SPEC COMPLIANCE (OBRIGATÓRIO)
**Critério**: Cada RF-ID da spec tem teste derivado passando + contrato de saída respeitado.

**Como verificar**:
- `grep -r "RF-" .planning/<feature>/specs/*.md` → lista RF-IDs
- Cada RF-ID deve ter `describe('RF-XXX')` ou `it('RF-XXX')` em test file
- `vitest run` → todos testes verdes
- Contrato Zod/TS em `## CONTRATO DE SAÍDA` da task spec → imports usam EXATAMENTE esse tipo

**Bloqueio**: RF-ID sem teste, teste falhando, contrato divergente.

## B2 — COVERAGE 100% (OBRIGATÓRIO)
**Critério**: `vitest run --coverage.enabled=true --coverage.reporter=json` → 100% statements/branches/functions/lines **nos arquivos criados/modificados na task**.

**Como verificar**:
```bash
# Cobertura apenas dos arquivos do diff
npx vitest run --coverage.enabled=true --coverage.reporter=json --coverage.include="src/modules/**/*.ts"
# Ou para arquivo específico:
npx vitest run --coverage.enabled=true src/modules/xyz/__tests__/xyz.test.ts
```

**Thresholds (vitest.config.ts)**:
```ts
coverage: {
  thresholds: {
    100: true,  // statements
    100: true,  // branches
    100: true,  // functions
    100: true   // lines
  }
}
```

**Bloqueio**: Qualquer % < 100 nos arquivos da task.

**Exceções documentadas (equivalentes reais, NÃO contam como gap)**:
- Ternários `music.MIN = 0` vs `music.MIN === 0` (mesmo bytecode)
- Regex IP mascarada (`\d{1,3}` vs `[0-9]{1,3}`)
- `0 <= 0` vs `0 < 0` (sempre true)
- `if (false)` dead code eliminado pelo bundler

## REGRAS DE OURO DO CRÍTICO (IMUTÁVEIS)

1. **ZERO INTERPRETAÇÃO** — Só o que está ESCRITO acima. "Eu acho que..." = NÃO É CRITÉRIO.
2. **BLOCKING** = Viola B1, B2 ou B4 (obrigatórios LITE). Ponto final.
3. **SHOULD_FIX** = Code smell real (DRY, complexidade ciclomática > 10, naming inconsistente com codebase). NÃO bloqueia merge.
4. **NICE_TO_HAVE** = Preferência subjetiva ("eu faria assim"). IGNORADO pelo loop.
5. **EQUIVALENTES REAIS** em mutation/coverage = NÃO SÃO GAP. Documentados acima em B2.
6. **MOCKS DEVEM ESPELHAR CONTRATO** — `vi.mock` com tipos exatos do contrato de saída da task spec.
7. **TESTES NODE vs JSDOM** — `vitest.setup.ts` protege `window` mock. Testes Node não quebram por `window`.
8. **PARIDADE WEB/DESKTOP** — Mudança no desktop (Electron) = teste no web (PWA) e vice-versa. Crítico verifica se há teste correspondente no outro target.
